AI DESIGN WORKFLOW · GENERIC FRAMEWORK

通用 AI 设计工作流：
从「生成一张不错的图」到「可交付的设计」

一套与具体业务无关的方法框架：把设计知识沉淀为 AI 可调用的资产，用结构化澄清把模糊意图收敛成可执行指令，再以流程契约和验收环保证生成结果达到交付标准。

意图收敛× 知识资产× 流程契约× 验收闭环= 可交付设计
01 · WHY

出发点：通用 AI 工具的「交付鸿沟」

通用 AI 工具能生成一个看起来不错的结果，但离复杂业务里的可用交付还有距离。差距不在模型，而在模型之外——它没有你的知识、资产、流程和判断标准。

看起来不错的图

风格合理、布局像样，但组件不合规范、状态残缺、术语误用、无法进入生产链路。

PRODUCTION GAP · 缺失项
设计工作流设计规范质量标准领域知识生产交付方式资产规则商业规则

可交付的设计

符合规范与品牌、状态完整、术语正确、附带说明与 Demo，可直接进入评审与开发。

结论：AI 生成之后仍需设计把控；要补的正是知识、资产、流程、判断标准这四类缺失——这就是整套工作流要解决的问题。

02 · PARADIGM

范式：设计的三个 From → To

工作流的底层假设是设计范式正在整体迁移——起点、过程、交付各变一次。

SHIFT 01

设计起点的重构

结构设计→意图驱动

从画框架开始，变成从表达目标与意图开始；结构由系统依据意图推导。

SHIFT 02

设计过程的升维

单项指令→多模共创

从一句 prompt 出一张图，变成文本、图像、规范、代码多模态往复共创。

SHIFT 03

设计交付的革新

静态方案→产品工程

交付物从静态稿升级为带状态、逻辑、代码结构的工程化产物。

03 · MODEL

核心模型：Human-in-the-AI-Loop 双环

设计对象从界面本身，变成人与 Agent 的协作闭环。上半环解决「意图如何进入系统」，下半环解决「结果如何被人评估」——整套工作流就挂在这两个半环上。

上半环意图表达

让模糊的人类目标被系统正确接收：结构化 Prompt、需求澄清、知识注入——对应本框架第 05、06 节。

下半环结果评估

让生成结果能被人高效审阅与验收：状态补全、说明文档、可交互 Demo、QA 自检——对应第 07 节。

设计师的新位置

从执行环节移到两端：定义进入系统的意图与规则，以及定义什么算好的结果。

04 · ARCHITECTURE

总架构：五层泳道 × 四阶段

纵向五层是系统的组成（谁在干活），横向四阶段是任务的推进（活怎么流转）。SKILL 层可插拔、REPOSITORY 层是全部知识资产的落盘——这两层决定了系统的可扩展性。

05 · KNOWLEDGE

06 · INTENT

意图收敛：9 维框架 + 澄清管线

模糊需求不能直接进生成环节。先用 9 维结构化框架定义「一个完整需求长什么样」，再用澄清管线把缺失维度补齐——能推导的自动补，推导不了的才反问，每站最多问 2 个问题。

GROUP 01需求定义与目标

1.1是什么

需求类型与页面目标，一句话定义页面

1.2有什么

页面包含的核心功能或模块

1.3长什么样

整体视觉风格与视觉基调

GROUP 02层级布局与信息架构

1.4页面结构

区域划分与自上而下的布局顺序

1.5模块结构

模块内部信息区域如何排列

1.6容器结构

具体 UI 容器、内容类型与字段

GROUP 03 ★设计意志 · 约束边界

1.7参数数值

明确的设计尺寸或视觉参数

1.8额外要求

状态、规则或需特殊强调之处

1.9禁止说明

需要避免的设计方向或限制

注意第三组：「禁止说明」被单列为一个维度——约束边界（不要做什么）与正向要求同等重要，这与知识底座里的反例库互为呼应。

07 · DELIVERY

交付标准：不止出图的四个交付级 Skill

「可交付」意味着生成结果要带齐评审与开发需要的一切。四个 Skill 定义了交付物的完整形态：

SKILL 01

链路状态补全

STATUS COMPLETION

自动识别并补齐正常 / 加载中 / 空态 / 异常等全部状态，再逐一校验。

识别 · 补全 · 校验
SKILL 02

汇报大图

PRESENTATION KEY VISUAL

把方案拆解、组织成一张可用于评审汇报的全景大图。

拆解 · 组织 · 呈现
SKILL 03

动态交互 Demo

INTERACTIVE DEMO

生成带触发与反馈的可交互演示，交互意图不再靠口头描述。

触发 · 反馈 · 演示
SKILL 04

设计总结说明

DESIGN SUMMARY NOTES

输出设计决策说明与复盘记录，让方案可追溯、可交接。

复盘 · 记录 · 交接
验收环（Evaluator）：交付前由评审 Agent 对照 QA 清单与规范卡自检评分，未达标项回到「校验修正」阶段定向重生成——验收是流程节点，不是人工兜底。
08 · SCENARIOS

先落地哪些活：四类高置信场景

阶段一的定位不是替代设计师，而是「设计助理」——专啃重复性 repetitive、结构化 structured、规范化 standardized 的工作。四类场景最先见效：

批量素材替换

BATCH ASSET REPLACEMENT

同一模板下批量换素材、换内容，规则明确、量大重复。

新增业务模块

ADD A NEW MODULE

在既有页面框架内按模板与组件规范插入新模块。

老旧页面翻新

LEGACY PAGE REDESIGN

按新规范批量刷新存量页面，规范迁移由 AI 执行。

多模态设计表达

MULTIMODAL PROMPT

用截图 + 文字 + 参考图混合表达意图，对话式迭代。

09 · PEOPLE

人的迁移：角色、能力与终局

工作流吃掉执行层之后，设计师的价值向两端移动——向前定义意图与规则，向后定义验收标准。

角色：从「执行者」到「共建者」

响应力协同方式变了

快速承接，天级交付

思考力交付产出变了

交付 AI 认知框架而非设计稿

体系力价值定义变了

定链路标准，体系化生产

架构力视野变了

设计生成规则，交付会生长的系统

参与度逐层加深：从「等待需求出现」到「定义系统本身」；价值尺度从「好不好看」变为「能不能转化」。

个人能力公式

craft×breadth×taste

craft 动手：亲手搭过，才有 1→10 打磨的工匠判断。

breadth 广度：岗位边界模糊化，产品 / 运营 / 开发技能要多线掌握。

taste 审美：不止视觉审美——交互、架构、代码审美共同决定交付层次。

传统图形界面 GUI→ 生成式界面 Generative UI→ 智能体与对话 Agent & Chat
「AI 会取代一部分设计师，但也会让另一部分『设计师』变得更强大和全面。」 Designers are not disappearing. Their boundaries are being redrawn.
10 · RECAP

整条工作流，一屏收束

  1. 沉淀知识资产　把规范、领域知识、反例做成带 AI ACTION 的编号卡片库，按层级归档为 md 资产（Spec Drives Gen-UI）。
  2. 收敛意图　9 维框架定义完整需求；澄清管线自动补全，推导不了才反问（每站 ≤2 问），产出结构化需求清单。
  3. 规划与生成　五层泳道协作：规划 Agent 推导结构 → 生成 Agent 调用组件与模板产出界面（图 / 代码）。
  4. 校验修正　评审 Agent 对照 QA 清单与反例库自检评分，未达标项定向重生成——验收是流程节点。
  5. 交付完整形态　状态补全 + 汇报大图 + 可交互 Demo + 设计说明，直接进入评审与开发。
  6. 人守两端　设计师定义意图与规则（上半环）、定义什么算好（下半环），沿 响应力→思考力→体系力→架构力 升级。
